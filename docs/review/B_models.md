## 3. Findings (leakage)
1. **HIGH — parity folds use future seasons.** build_data.py:769 `f = M["folds"]["odd" if season % 2 == 0 else "even"]`; train_stuff.py:47 `sub = [x for y, x in parts if y % 2 == par]`. 2022 is graded by models trained on 2021, 2023, 2025 (future data); grades/expected rates for past seasons encode later-season league trends, and backtests "next-season r" (2022→23) evaluate on a season inside the scoring model's training set. Not "out of sample" in time, only out of season. Fix: forward-chaining (score Y with models trained ≤ Y−1) for any forecasting claim; keep parity only for descriptive grades. VERIFIED.
2. **HIGH — directional xwOBA/xBA/xSLG are in-sample for every season 2015–2026.** model3.py:63 `m.fit(bbe[FEATS], bbe["y"], sample_weight=w.values)` on all seasons, then every season is rescored with it. Same-season r (.890 vs wOBA) and "first half→second half" tests in CLAUDE.md are inflated; current-season xwOBA includes the season's own outcomes (weighted most heavily, weight 1 for ANCHOR). Fix: leave-one-season-out fits for scoring, or train ≤Y−1. VERIFIED.
3. **MED — early-stopping validation is random rows.** model3.py:61-62, build_data.py:794 `early_stopping=True, validation_fraction=0.1` — sklearn holds out random pitches/BBE, same pitcher/batter/game/season on both sides; stopping point optimistically chosen (correlated rows), mild overfit. Fix: pass a grouped (by pitcher-season or game) holdout and train without internal ES, or set n_iter from grouped CV. VERIFIED (code); effect size SUSPECTED small.
4. **MED — pitcher-identifying features.** stuff_features L639-646 per-pitcher-season primary-FB reference (velo/IVB/HB gaps), `use`/`depth` (his usage that season), release-point spread `relsd` (now excluded via `STUFF_UNUSED`, build_data.py:670). Gaps+usage act as pitcher fingerprints; with fold training on same pitcher's other seasons the model can memorise pitcher identity → expected rates drift toward actual (the "20–30% toward actual" note). Usage is also partly outcome-driven (pitchers throw what works) → target leakage. Fix: drop `use` or test grouped-by-pitcher CV. SUSPECTED.
5. **MED — fallback path trains on the season it grades.** build_data.py:743-746 `train = pd.concat([prior, d[...]])` then `_grade_stuff(M, d)` — when the joblib is missing, the current season is fully in-sample (also minors with `ref` uses MLB same season). VERIFIED.
6. **MED — park model in-sample.** build_parks.py:109 `clf.fit(X, yv); P = clf.predict_proba(X)` and :190-192 park-aware vs park-blind fit and scored on same balls; venue category with ~thousands of balls per venue-season will absorb noise, inflating park effects (shrinkage n/(n+60) only partly offsets). Fix: K-fold out-of-fold predictions. VERIFIED.
7. **LOW-MED — selection/tuning outside CV.** Hyperparams, feature choices (seq features, `XHRFB`, `TW_GB` constants, weight 0.6/0.4 etc.) chosen by scratch backtests on the same seasons later reported; nested selection only claimed for the 14 Nov ridge. Expect reported gains optimistic. SUSPECTED.
8. **LOW — retrain.yml rescores with models whose ANCHOR equals the current season** (weight 1 on the live, partial season), so live expected stats shift at each retrain. VERIFIED by model3.py:23 default.
9. **LOW — command models leak count/outcome sequencing:** `swing`/`call` use balls/strikes; prior-pitch `pv_*` features use the pitch before's result in the same PA (seq). Within-PA info, not the label itself — acceptable but makes "location" partly sequencing. SUSPECTED.
